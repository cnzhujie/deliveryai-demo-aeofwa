# 1. 需求背景

- **需求类型**: ☑ 用户反馈
- **背景 / 驱动**: 当前欢迎页（WelcomeView）在绑定餐桌后仅展示门店图片、问候语和"进入点餐"按钮，用户在进入菜单页前无法获知门店有哪些值得关注的菜品。增加推荐菜品预览，可以让用户在进入菜单页前就形成初步选择意向，提升点餐决策效率。
- **用户价值**: 顾客在欢迎页即可快速浏览门店推荐菜品（人气、招牌、主厨推荐、新品），减少进入菜单页后的选择成本。
- **关联重点特性**: 无

| 用户角色 | 核心场景 | 痛点 | 相关 SA |
|----------|----------|------|---------|
| 顾客 | 绑定餐桌后、进入菜单前的过渡阶段 | 无法预知热门菜品，需进入菜单页后逐一浏览 | WelcomeView |

# 5. 功能需求

## REQ-001: 欢迎页展示推荐菜品区块

**User Story**
> As a 顾客, I want 在欢迎页看到门店推荐菜品, so that 进入菜单前就能了解热门菜品并形成初步选择。

**Priority**: P0

**需求描述**
在 WelcomeView 的问候语区块与「进入点餐」按钮之间，新增推荐菜品区块。该区块以横向滑动卡片形式展示 4 道带有 badge 标签的推荐菜品（p1 人气 No.1、p2 招牌、p3 主厨推荐、p5 新品），每张卡片包含菜品图片、名称、价格和 badge 标签。卡片仅做展示预览，不支持直接加菜。

**Acceptance Requirements**
- **REQ-001.1**: The system **shall** 在 WelcomeView 问候语区块下方、进入点餐按钮上方展示推荐菜品区块。
- **REQ-001.2**: The system **shall** 从现有 `products` 数组中筛选 `badge` 字段存在的菜品，按 `products` 数组原始顺序排列。
- **REQ-001.3**: The system **shall** 每张推荐菜品卡片包含菜品图片、菜品名称、价格和 badge 标签。
- **REQ-001.4**: The system **shall** 推荐菜品以横向可滑动卡片形式展示，支持用户左右滑动浏览。
- **REQ-001.5**: **When** 页面在移动端窄屏（< 640px）展示时，**then** 推荐菜品卡片应可横向滚动，不溢出页面宽度。
- **REQ-001.6**: **When** 页面在桌面端宽屏（≥ 640px）展示时，**then** 推荐菜品卡片横向排列，若空间不足应支持横向滚动。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 绑定餐桌后进入欢迎页 | 展示门店图片、问候语、推荐菜品区块、进入点餐按钮 |
| 2 | 左右滑动浏览推荐菜品 | 卡片横向滚动，展示不同推荐菜品 |
| 3 | 点击「进入点餐」按钮 | 跳转至菜单页（MenuView） |

**关联埋点**: 无（概念演示项目）
**实现映射**: Tasks T-001

## REQ-002: 推荐菜品区块样式与国际化

**User Story**
> As a 顾客, I want 推荐菜品卡片风格与整体页面一致且支持中英文, so that 视觉统一且无语言障碍。

**Priority**: P0

**需求描述**
推荐菜品区块的视觉风格需与 WelcomeView 现有设计语言一致（圆角卡片、Tailwind 类名硬编码、chili/amber/rice/charcoal 色板）。新增的区块标题文案和卡片标签需在 `i18n.ts` 的 zh/en 两处同步添加。

**Acceptance Requirements**
- **REQ-002.1**: The system **shall** 推荐菜品区块标题使用 i18n key，支持中英文切换。
- **REQ-002.2**: The system **shall** badge 标签使用现有 i18n key（`menu.badge.popular` 等），不新增 badge 文案。
- **REQ-002.3**: The system **shall** 价格使用现有 `money()` 工具函数格式化为 `¥XX` 格式。
- **REQ-002.4**: The system **shall** 样式遵循 AGENTS.md 约定：仅使用 Tailwind 类名，颜色使用 `rice`/`charcoal`/`chili`/`amber` 色板，不引入 CSS Modules 或额外 UI 库。
- **REQ-002.5**: **If** 语言切换为英文，**then** 推荐区块标题和菜品名称应正确显示英文。

**用户交互**

| 步骤 | 用户动作 | 产品响应 |
|------|----------|----------|
| 1 | 在欢迎页切换语言 | 推荐区块标题、菜品名称、badge 标签切换为对应语言 |

**关联埋点**: 无
**实现映射**: Tasks T-002

# 验收标准

- [主流程] 在【已完成桌台绑定，进入欢迎页】下，用户应【看到推荐菜品区块，包含 4 道带 badge 标签的菜品卡片，展示图片、名称、价格和标签】。
- [交互] 在【欢迎页推荐菜品区块】下，用户【左右滑动】后，应【看到更多推荐菜品卡片横向滚动展示】。
- [跳转] 在【欢迎页】下，用户点击【进入点餐】按钮后，应【正常跳转至菜单页，功能与改动前一致】。
- [边界约束] 本次改动不应影响【WelcomeView 现有的门店图片、问候语、进入按钮功能，以及 BindTable → WelcomeView → MenuView 的视图流转】。
- [内容正确性] 展示的推荐菜品应符合【products 数组中 badge 字段存在的菜品，按数组顺序排列，共 4 道】。
- [国际化] 切换语言为【英文】时，推荐区块标题和菜品名称应【正确显示英文】。
- [异常处理] 当出现【所有菜品均无 badge】时，系统应【优雅隐藏推荐区块或不展示，不影响页面其余功能】。
- [兼容稳定] 变更后【老人模式、深色模式、移动端/桌面端布局】保持正常，无明显异常。
